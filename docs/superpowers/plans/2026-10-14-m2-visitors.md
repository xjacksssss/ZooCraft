# M2 Visitors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Villager visitors arrive alone or in groups, pay admission exactly once, wander the zoo, and always leave, including when the zoo closes, a gate is blocked or the boundary changes (spec section 7).

**Architecture:** A `Visitor` entity (`PathfinderMob` + SmartBrainLib `SmartBrainOwner`, villager model and biome skin). SBL library behaviours handle walking (`MoveToWalkTarget`), doors (`InteractWithDoor`) and looking around. One custom SBL behaviour, `VisitBehaviour`, runs the visit state machine (`VisitorController`), which only ever sets the walk target and phase. A custom node evaluator applies the boundary rule and the path-block preference. A per-zoo spawner and a visitor tracker run on server ticks. Optional chunk loading uses NeoForge's `TicketController`.

**Tech Stack:** SmartBrainLib 1.16.11, vanilla pathfinding, NeoForge `TicketController`, entity data serializers.

**Spec:** `docs/superpowers/specs/2026-10-14-phase1-prototype-design.md` (section 7)

**Execution note:** The user asked for uninterrupted execution. Plans list exact files, interfaces and tests; code is written during execution, test first where the logic is pure.

## Global Constraints

- Admission goes only through `ZooManager.chargeAdmission(zoo, visitId, price)`; the visitor deducts its budget and sets `admitted` only when it returns APPLIED.
- Visitors never despawn naturally and are invulnerable to everything except `/kill`.
- Every visitor must leave within `maxVisitMinutes` plus the 60-second exit safety net.
- Visitor counts: at most `maxVisitorsPerZoo` per zoo and `maxVisitorsTotal` per server.

## Review Focus

- A group where one member can't afford entry: nobody pays (GameTest).
- The only gate walled off after admission: the visitor is released within the safety-net time and the complaint is recorded (GameTest).
- Closing the zoo with visitors inside: all leave (GameTest).
- A visitor saved inside an unloaded chunk for longer than a visit: its visit ends when the chunk loads (unit-tested decision in `VisitorController.shouldExpireOnLoad`).
- Visitors pushed outside the boundary by a player: they are released rather than trying to re-enter without paying (handled by the outside-boundary check in `VisitorController`).

### Task 4: Visit state machine, groups, admission, leaving and safety net

**Files:**
- Create: `src/main/java/com/zoocraft/visitor/VisitorController.java`, `VisitBehaviour.java`, `VisitorGroups.java`, `Admission.java`, `OpenFenceGates.java`
- Modify: `ZooManager` (`recordDeparture`, `recordComment`, `recordRefusal`)
- Test: `src/main/java/com/zoocraft/gametest/VisitorGameTests.java`

**Produces:**
- `Admission.tryAdmitGroup(Zoo, List<Visitor>) -> boolean` (all-or-nothing, exactly once per visit ID).
- Controller rules: ARRIVING walks to the gate's outside point; QUEUEING waits for the group (up to 20 s) then the leader runs admission; EXPLORING wanders reachable points (M3 replaces this with exhibits) and leaves on closing, timeout, low interest or low satisfaction; outside the boundary while exploring means release; LEAVING walks to the nearest usable gate, marking gates blocked when no path; EXITING walks 16 blocks outward then fades; REFUSED walks away then fades.
- Safety net: no progress for 30 s means a new route; 3 failures in a row while exploring means LEAVING, while leaving means try another gate; 60 s after starting to leave without getting out means fade out with `COULD_NOT_LEAVE`.
- `ZooManager.addBoundaryListener` and `addRemoveListener` release affected visitors.

GameTests: admission charged once even when re-triggered; group refuses together with no money moved; closing the zoo makes visitors leave; walled-off gate releases the visitor with the complaint; boundary edit leaving a visitor outside releases it.

### Task 5: Spawner, tracker and chunk loading

**Files:**
- Create: `src/main/java/com/zoocraft/visitor/VisitorTracker.java`, `VisitorSpawner.java`
- Create: `src/main/java/com/zoocraft/chunk/ZooChunkLoader.java`
- Create: `docs/playtests/m2-visitors.md`

**Produces:**
- `VisitorTracker.count(UUID zooId)`, `total()`, `visitors(UUID zooId)`, kept up to date from entity join and leave events.
- Spawner: every `spawnIntervalSeconds` per open zoo; chance `0.35 + reputation / 200`; group size weighted 1:45%, 2:30%, 3:15%, 4:10%; spawn 16–32 blocks outside a random usable gate, in a ticking chunk, outside all zoos, with a checked path; alert flag "visitors can't find a way to your gates" after 5 failed attempts in a row.
- Chunk loader keeps boundary chunks plus a 2-chunk margin loaded for zoos with keep-loaded on, capped by config.
