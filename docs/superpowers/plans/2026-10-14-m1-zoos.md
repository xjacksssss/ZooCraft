# M1 Zoos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Players can create, edit, save and manage custom-shaped zoos with gates, owners, managers and a treasury (spec section 6).

**Architecture:** Pure geometry and ledger logic in `com.zoocraft.core` (JUnit). A mutable `Zoo` object with Codecs, stored in one overworld `ZooSavedData`, accessed only through `ZooManager`. Tools hold per-player drafts on the server and sync them to the client for rendering. Commands use Brigadier and route through the same `ZooManager` methods as the tools.

**Tech Stack:** NeoForge 21.1.251, JTS 1.20.0, Codecs, `SavedData`, NeoForge payloads, `RenderLevelStageEvent`.

**Spec:** `docs/superpowers/specs/2026-10-14-phase1-prototype-design.md` (section 6)

**Execution note:** The user asked for uninterrupted execution. Plans list exact files, interfaces and tests; code is written during execution, test first.

## Global Constraints

- All zoo state changes happen on the server thread through `ZooManager`.
- No zoo operation may remove or change world blocks.
- Every player-facing string goes through `en_us.json` with British spelling.
- Boundary defaults: min area 64, max area 65,536, max 64 vertices; gates within 3 blocks of the edge.
- A zoo can't be deleted while its treasury is above zero.

## Review Focus

- A boundary drawn clockwise vs anticlockwise must behave identically. JUnit covers both orders.
- Two consecutive identical corners (double-click) must not break validation. The draft ignores a corner equal to the previous one; JUnit covers the validator with a repeated vertex.
- Zoo names with spaces and different case: names are unique case-insensitively, commands accept quoted names. GameTest covers duplicate-name rejection.
- Deposit with an inventory holding emerald blocks and emeralds across several stacks: exact count removed. GameTest covers it.
- A player who is both owner and op, or neither: the permission check uses op level 2 as an override. GameTest covers a non-manager being refused.

### Task 1: Boundary geometry (pure)

**Files:**
- Create: `src/main/java/com/zoocraft/core/geometry/Vertex.java` (`record Vertex(int x, int z)`)
- Create: `src/main/java/com/zoocraft/core/geometry/BoundaryLimits.java` (`record BoundaryLimits(int minArea, int maxArea, int maxVertices)`)
- Create: `src/main/java/com/zoocraft/core/geometry/ZooShape.java`
- Create: `src/main/java/com/zoocraft/core/geometry/BoundaryValidator.java`
- Create: `src/main/java/com/zoocraft/core/geometry/BoundaryProblem.java`
- Test: `src/test/java/com/zoocraft/core/geometry/BoundaryValidatorTest.java`, `ZooShapeTest.java`

**Produces:**
- `ZooShape.of(List<Vertex>)`; `boolean containsBlock(int x, int z)` (block centre inside or on edge); `double distanceToEdge(double x, double z)`; `double[] outwardNormalAt(double x, double z)` (unit vector of the nearest edge pointing outside); `double area()`; `int minX(), maxX(), minZ(), maxZ()`; `boolean overlaps(ZooShape other)` (interiors intersect with area > 0); `LongSet coveredChunks()` (chunk positions packed with `ChunkPos.asLong` maths, no MC import).
- `BoundaryValidator.validate(List<Vertex>, BoundaryLimits, List<NamedShape> others) -> Optional<BoundaryProblem>`; `record NamedShape(String name, ZooShape shape)`.
- `BoundaryProblem` record: `Kind kind` (`TOO_FEW_CORNERS`, `TOO_MANY_CORNERS`, `SELF_INTERSECTING`, `TOO_SMALL`, `TOO_LARGE`, `OVERLAPS`), `Vertex at` (nullable), `String otherZoo` (nullable), `long limit`.
- Vertices are treated as block centres (`x + 0.5`, `z + 0.5`). Consecutive duplicates are removed before validation.

Tests: square valid; clockwise and anticlockwise equal; 2 corners → TOO_FEW_CORNERS; bow-tie → SELF_INTERSECTING with an `at` point; 4x4 → TOO_SMALL; 300x300 → TOO_LARGE; 65 vertices → TOO_MANY_CORNERS; overlap → OVERLAPS naming the other zoo; touching edge allowed; repeated consecutive vertex ignored; `containsBlock` on interior, edge and outside blocks; `outwardNormalAt` on each side of a square; `coveredChunks` of a 40x40 square at the origin has 9 chunks.

### Task 2: Ledger (pure)

**Files:**
- Create: `src/main/java/com/zoocraft/core/ledger/Ledger.java`, `Transaction.java`, `TransactionType.java`, `LedgerResult.java`
- Test: `src/test/java/com/zoocraft/core/ledger/LedgerTest.java`

**Produces:**
- `enum TransactionType { DEPOSIT, WITHDRAW, ADMISSION }` (positive for DEPOSIT and ADMISSION, negative for WITHDRAW).
- `record Transaction(String key, TransactionType type, long amount, long gameTime, String actor)`; `amount > 0` always.
- `enum LedgerResult { APPLIED, DUPLICATE, INSUFFICIENT_FUNDS, INVALID_AMOUNT }`.
- `Ledger`: `long balance()`, `LedgerResult apply(Transaction)`, `boolean hasKey(String)`, `List<Transaction> recent()` (newest first, at most 200), `long totalAdmission()`, `long totalDeposits()`, `long totalWithdrawals()`, plus a constructor taking all persisted state for Codec use. Keys are remembered for the most recent 10,000 transactions.

Tests: deposit then withdraw; overdraw rejected and balance unchanged; repeated key rejected and balance unchanged; zero or negative amount rejected; recent list capped at 200; totals add up; key memory capped at 10,000 with the oldest dropped first.

### Task 4: ZooManager and permissions

**Files:**
- Create: `src/main/java/com/zoocraft/zoo/ZooManager.java`, `ZooPermission.java`, `ActionResult.java`, `ZooEvents.java` (server lifecycle hooks: load index on server start)
- Create: `src/main/java/com/zoocraft/zoo/Emeralds.java` (count, remove and give emerald items)
- Modify: `src/main/resources/assets/zoocraft/lang/en_us.json`
- Test: `src/main/java/com/zoocraft/gametest/ZooManagerGameTests.java`

**Produces:**
- `ZooManager.get(MinecraftServer)`.
- `ActionResult`: `boolean success()`, `Component message()`; factories `ok(Component)`, `fail(Component)`.
- `enum ZooPermission { VIEW, EDIT, SETTINGS, FINANCES, MANAGE_MANAGERS, TRANSFER, DELETE }`; `boolean ZooManager.can(ServerPlayer, Zoo, ZooPermission)` (owner all; manager all except MANAGE_MANAGERS, TRANSFER, DELETE; op level 2 all).
- Methods (each returns `ActionResult`, checks permission, marks dirty, fires `ZooChangedEvent`-style callback `onZooChanged(Zoo)` that later milestones hook): `createZoo(ServerPlayer, String name, ResourceKey<Level>, List<BoundaryVertex>)`, `editBoundary(ServerPlayer, Zoo, List<BoundaryVertex>)` (returns detached gate report), `addGate(ServerPlayer, BlockPos)`, `removeGate(ServerPlayer, BlockPos)`, `setOpen(ServerPlayer, Zoo, boolean)`, `setPrice(ServerPlayer, Zoo, int)`, `setKeepLoaded(ServerPlayer, Zoo, boolean)`, `addManager(ServerPlayer, Zoo, GameProfile)`, `removeManager(ServerPlayer, Zoo, UUID)`, `transfer(ServerPlayer, Zoo, GameProfile)`, `rename(ServerPlayer, Zoo, String)`, `delete(ServerPlayer, Zoo)`, `deposit(ServerPlayer, Zoo, int)`, `withdraw(ServerPlayer, Zoo, int)`.
- Lookup: `Optional<Zoo> zooAt(Level, BlockPos)`, `Optional<Zoo> byName(String)`, `Optional<Zoo> byId(UUID)`, `List<Zoo> managedBy(ServerPlayer)`, `Collection<Zoo> all()`.
- `ZooManager.addChangeListener(Consumer<Zoo>)` and `addRemoveListener(Consumer<Zoo>)` for later milestones (visitors, sync).
- Gate placement: the gate is attached to the zoo whose edge is within 3 blocks; `outside`/`inside` are the gate position moved 2 blocks along the outward normal and against it, snapped to blocks. A warning is returned if either is not standable.
- `Zoo.gateStatus`: DETACHED when the gate is more than 3 blocks from the edge, BLOCKED when marked blocked by visitor code within the last 2 minutes, otherwise OPEN.

GameTests: create succeeds and owner set; overlapping create refused; duplicate name refused; manager can set price but not add managers; non-manager refused; edit that moves the edge away detaches a gate and keeps treasury; delete with funds refused, after withdraw succeeds; deposit removes exactly the right emeralds from mixed stacks (blocks count as 9) and withdraw gives them back; withdraw more than balance refused with nothing given.

**Produces:**

- Boundary Tool controls (create mode): use on block adds a corner (duplicate of last is ignored); use on the first corner with at least 3 corners closes and opens the naming screen; sneak-use on block undoes the last corner. Edit mode is entered by using the tool inside a managed zoo with no draft: use near a corner picks it up, next use puts it down; sneak-use on an edge inserts a corner; sneak-use on a corner deletes it; chat shows clickable [Save] and [Cancel] that run `/zoo boundary save|cancel`. Create mode chat shows [Discard].
- Designation Tool: use on block adds a gate; sneak-use on an existing gate removes it.
- Client rendering: draft lines in yellow, saved zoo outlines in green, gates as small boxes (open green, blocked red, detached grey), shown while holding either tool.
- Server sends `ZooOutlinesPayload` (zoos within 8 chunks) to tool holders every 40 ticks and after any change.

DraftOps JUnit tests: nearest vertex, nearest edge, insert, move, remove.
